# Заказы и выручка по артикулам и дням

Скрипт читает выгрузку заказов `sales.csv` и строит `daily_by_sku.csv`: по строке на пару «артикул — день» с колонками `sku, order_date, orders, revenue`.

## Как запустить

Нужен Python 3.8+. Скрипт использует только стандартную библиотеку, ставить ничего не надо.

```
python daily_by_sku.py                # читает ./sales.csv, пишет ./daily_by_sku.csv
python daily_by_sku.py in.csv out.csv # или с явными путями
```

Результат появится в `daily_by_sku.csv` рядом со скриптом (в git он не попадает, см. `.gitignore`). `sales.csv` в репозитории нет — положите его в корень.
## Как проверяли

- `check.py` пересчитывает всё независимо, через pandas (`pip install pandas`), и сравнивает с файлом скрипта построчно. Запуск: `python check.py`. Должно напечатать `OK`.
- Контрольные цифры: в выгрузке 13 858 строк и 13 798 уникальных `order_id`; сумма `orders` в результате = 13 798. Общая выручка = 10 276 540. Строк в результате 631, пар «артикул — день» повторяющихся нет.
- Выручку сверяла «по разнице»: сумма по доставленным без дедупликации и с нормализацией статусов — 10 319 900; минус выручка 52 дублей доставленных заказов (43 360) даёт ровно 10 276 540.
- Глазами проверила несколько пар «артикул — день» на сыром файле.

## Проблемы в данных и что с ними сделала

- **Полные дубли строк: 60** (одинаковый `order_id`, и все остальные поля тоже). Оставляю первую строку, остальные пропускаю. Дубли с разным содержимым при одном `order_id` в выгрузке не встретились; на такой случай скрипт оставит первую строку и напишет счётчик конфликтов в stderr.
- **Статусы с разным написанием:** `Delivered`, `DELIVERED`, `delivered ` (с пробелом), `Cancelled`, `CANCELLED`, `canceled`. Привожу к нижнему регистру, обрезаю пробелы, `canceled` → `cancelled`. Без этого потерялось бы 25 доставленных заказов на 23 100 выручки.
- **Пустое `quantity`: 4 строки.** Все четыре со статусом cancelled, на выручку не влияют, в `orders` считаются. Если бы пустое количество встретилось у delivered, скрипт упадёт с ошибкой, а не посчитает молча неверно.
- Проверил и не нашёл проблем: формат дат, формат артикулов, пропуски в других колонках, разброс цен (у каждого артикула одна цена).
